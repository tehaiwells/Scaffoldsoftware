# Remaining acceptance gaps and operating limits

This is a working local demonstration of the core round trip and stock control. It is not a claim that every detail of the full commercial V1 brief is complete.

1. Yard lists (multi-line load lists) now exist: the office lists several products for one site, the yard reserves exact packs line by line (all-or-nothing per line, short lines are reported with the reason and can be re-planned), the truck loads, and the same list travels with the truck as the delivery docket with the sent quantities frozen at departure. Lines cannot be edited after creation — cancel the list and re-list. A line whose loading task is cancelled after planning becomes PARTIALLY ALLOCATED and blocks departure until the list is cancelled and re-listed. The older single-product request form remains as a quick one-line request.
2. The main yard view currently opens the first company yard. The API supports additional yards, but a multiple-yard selector and guided multi-step onboarding UI remain. Sites start as a 20 × 16 m rectangle. Yards and sites are now edited in one shape editor (Change yard shape & size next to the size in the LIVE YARD PLAN header, and the same editor on each site): a flat top-down plan with every side's length and a number on every corner (the same numbers appear on every yard and site plan), Rectangle, L-shape and Custom presets, Width and Depth fields with a corner that stays put, draggable corners, sides, loading zone, gate and fixtures, Undo/Redo and one Save button whose label and sentence say what saving will do. The shape is always closed; the old direction + length lines and the separate close-perimeter step are gone. Boundaries are stored as corner points; the segments API is still accepted as legacy input. A record left over from the old line builder with a slanted closing side opens with a notice and a one-click square-up. Saves are guarded by a shape revision: only another shape save or a site rename conflicts with an open editor, while the crew's automatic sweeps and parking changes never do. A rename-only or height-only save has no side effects (nobody is stopped, nothing moves, the loading zone and gate stay as they are). The loading zone and gate move to the nearest clear spot only when the new shape covers them. Checks run as you type: a quick preview (a few milliseconds) lists the stillages that must move, crew orders that will be stopped and movements that will be stopped or re-planned, and a full dry run shows where each one would go within a 400 ms budget; past the budget the new spots are chosen when you save. The yard can be resized at any time: stillages that would fall outside the new boundary, sit on the loading zone or exceed a lowered height are moved to clear ground inside it (stacks are set down), each move recorded as a RELOCATED ledger event; crew left outside or under a moved stillage are re-seated; the loading zone and gate fall back to the nearest fitting spot. Boundary relocation is still the one direct-write exception to crew-performed movement: it keeps each stillage's rotation and puts it at the first clear spot found, which is not an optimised layout. Resizing works with workers and forklifts present. A save that only enlarges the ground (the new shape contains the old one, the loading zone, gate and fixtures are unchanged and the height is not lowered) leaves the crew alone: nobody is stopped, no yard job is handed back and no movement is re-planned. Any other shape change stops manual drives and walks (loads stay on the forks), hands yard jobs back for re-assignment, moves mounted forklifts with their drivers and re-plans in-flight automatic movements against the new boundary. A waiting turn or layout step is stopped (BLOCKED with the reason; cancel it and plan again) when the new shape covers its spot, when the save moves its own stillage, when the save moves the stillage it was going to be stacked on, or when a lowered height makes its stack too tall. Before anything is lifted the engine re-checks every destination against the current shape, loading zone, fixtures, height and the stillage underneath. The save message names the real reason for each move (outside the new boundary, off the loading zone, clear of the fixtures, or set down for the new height). A resize is refused when the area is too small for its stock, when a stillage is currently on handling equipment, or while a load on the forks is heading for a spot the change would cover, a stillage the change would move, or a stack the new height would make too tall (wait until it has been set down). The gate is drawn on the plan but does not yet drive truck entry routing and is not kept clear of stock.
3. Routing is a conservative 500 mm grid with sampled swept footprint checks. It can reject a geometrically possible narrow route. One machine route runs per handling area to avoid conflicting moving loads. The machine/worker graphics are symbolic state displays, not continuous real-time physics. Detailed operator walking-to-machine paths, arbitrary manual-handling profiles and measured 30 FPS rendering remain. Manual hand carrying is not automatically allowed.
4. Simulation timing is a company-level configuration shared by its yards/sites. Crane resource counts are separate, but pickup and placement share the configured demo step time. Per-machine timing and full reach/support rating models need further work.
5. The yard plan has zoom (buttons or scroll), 45-degree rotation, drag-to-pan and a 3D (isometric) toggle that draws stillages as stacked boxes with their contents on hover and on the cards; the view is remembered per browser. It is a projected drawing, not a physics scene. The browser supports click-to-move and HTML container-card drag/drop; direct dragging of the SVG yard shape, custom ghost placement previews, tablet touch dragging and broad accessibility/device validation remain. Native browser drag ghosts are used. Exact placement and 90-degree orientation are available in the click alternative.
6. Stock views and container visuals are limited to 100 containers per page. Company totals and CSV exports cover all scoped stock. Stock search searches the current page; server-side global catalogue search/category filters remain. The STOCK page now has a per-product materials register (yard / sites / trucks / reserved / available), an added-stock list (opening balances and purchases) and a removed-stock list (sales and disposals); removals refuse reserved, in-transit and count-locked stock. Register and list CSV exports cover all scoped stock. The API still reads a company's object records to produce a page, so this is not a claim of million-row scale readiness. History uses indexed cursor pagination; CSV history is capped at 10,000 rows.
7. The persistence layer uses relational tenant/membership/content/ledger tables plus versioned JSON domain objects. References between JSON objects are validated by domain commands, not all by SQL foreign keys. A fully normalized production schema and PostgreSQL adapter/migration remain; PostgreSQL has not been tested.
8. Secure local sessions and role boundaries work. Password change/reset/recovery, membership removal, role editing, invite acceptance, distributed throttling and independent security review remain before public deployment. Financial permission is reserved; no financial screens/data exist.
9. Company records in this application are simulation workspaces only. There is no live-mode switch. Future real operations must use a separate confirmation adapter and explicit authorized confirmations, never the simulation timer. Do not mix real operational records into demo companies.
10. No manufacturer catalogue has been verified. No certified stacking, lift, load restraint, axle-load or road-legality calculations are provided. See CATALOGUE_PROVENANCE.md.

Known safe failure behavior: missing equipment/path/weight produces an explanation; busy equipment queues. Cancel before pickup releases reservations. After pickup, finish/retry valid placement; no teleporting undo exists. A blocked post-pickup task retains its cargo and resources. Automatic relocation planning and an alternate-destination recovery editor remain; configuration/path problems must be resolved before retrying.


## Overview page
The Overview page shows crew tiles (workers, workers tasked, workers idle, forklifts; site cranes for supervisors) and, per truck class (12.5 tonne and 2 tonne), four tiles that partition the fleet: Scheduled (booked, nothing loaded), Loading (a forklift is on it, or loaded and waiting to leave), Unloading (load on: on the road, or arrived and being emptied at the site or back at the yard) and Complete (empty and free; the sublabel counts loaded legs finished today on the server's local date). Below it, "Stock in yard" lists each material's pieces, reserved and free-to-load figures for that location only (damaged and quarantined stock is not free), and the site list opens a card on hover, click or Enter with the address, client details, supervisor, trucks and the materials on that site. Client company, site contact, email and phone are optional site fields edited on the Client sites page by operations users. To make the tiles honest the engine now clears a truck's booking when its last request or yard list is cancelled or a cancelled load is emptied at the yard, closes a short request once its remainder is at the site, counts a container as delivered once it has been placed off the truck, and finalises a delivery still marked arrived when the truck leaves again (DELIVERED if anything was placed, otherwise RETURNED). Hover cards are mouse and pen only; touch pins with a tap. Runs-today uses the server machine's local date.

## Stock corrections and the Home layout plan
Opening a stillage's details (from the Stock page, the yard plan or Home) now lists a "Remove" control under each material it holds, so an incorrect materials list can be corrected without waiting for a sale or a stocktake. It removes unreserved pieces from that exact stillage and records the reason on the removed-stock ledger; reserved, in-transit and count-locked pieces are protected the same as every other removal. It needs the stock.adjust permission and the stillage must be at a yard or site, not on a truck or handling equipment. The Home page now also carries the full layout planner ("Plan a new layout", drag-and-drop, Check plan, Commit this plan): starting a plan on Home keeps it open when you switch to the Yard page and back, and it is the same in-progress plan either way.

An empty stillage still removes with the plain "Remove stillage / cage" button, unchanged. A loaded one can now be removed outright too: its detail panel gets a "Remove this stillage anyway" control that writes off everything still on it (one removed-stock entry per material, with the typed reason) and then removes the stillage itself, in one action. It needs both operations.manage and stock.adjust, refuses while the stillage is busy (on a forklift, mid-move, or something stacked on top of it) or on a truck, and cannot be undone — it is meant for a stillage that is genuinely gone (lost, destroyed, unrecoverable), not for a quantity mistake, which the per-line Remove control above it is for.

## Yard jobs (Workers tab)
Every worker carries the ten skill categories from the brief (truck operations, order preparation, returns processing, material handling, stock control, yard organisation, equipment checks, maintenance/preparation, safety tasks, continuous improvement), all on by default and switchable per worker; the sub-task phrases are the job vocabulary. The Workers tab gives each worker Stop, Automatic/Hold, Move (to the loading zone, gate, a fixture, beside a forklift, a selected stillage, or a spot picked on the plan), Mount forklift, Unmount forklift, Next up, Allocate (a chosen open job) and Take off, plus Allocate all idle, All automatic and Hold all. Jobs are derived from the real yard state on stable keys and placed on the priority ladder (P1 trucks and hazards, P2 loads with a truck booked, P3 lists waiting for a truck, P4 returned material, P5 consolidate/sort stillages, P6 cycle counts, P7 yard organisation and equipment checks, P8 cleaning and improvement); an automatic worker takes the highest open job their skills allow and walks to it, then rotates through routine work so nobody stands still. Custom jobs can be added with a category, a place and a demo duration. Real effects exist only where the simulation has physical truth: unloading a truck that came home with returns (forklift moves queued), consolidating or sorting stillages within 8 metres (hand carry, ledger rows CONSOLIDATED/SORTED with an engine actor) and stacking loose empties (a forklift move). Load checks and pre-checks compute against the yard list; cycle counts, returns checks, pre-start checks, stack checks, sweeps and cleaning are recorded work with a timer and never open a stocktake, change a condition or write stock ledger rows; routine work is never listed as done work. The forklift engine keeps first pick: a truck load or repack takes an automatic worker off any yard job (the job returns to the board with its progress) and the shortage message names the cause when skills are the reason. Held workers are never auto-assigned. Yard lists carry no dates, so "today" and "tomorrow" are approximated by whether a truck is booked. The job engine runs in its own savepoints with a fault breaker; the movement engine keeps running if it fails. Walking uses the same conservative routing as manual moves; a job whose spot cannot be reached cools down and is shown as blocked after three tries (it reopens after 30 seconds), and routine work whose usual spot is blocked is done where the worker stands. Stock placement still does not treat workers as obstacles; a worker a stillage lands on is re-seated on clear ground the next time they are given work or an order. Cancelling the engine's automatic unload of a returned truck is respected for that delivery; the Unload button still works. A route-blocked movement gets one "clear a forklift route" job until it is retried. While a forklift move is waiting for a worker, one worker with the matching skill is held back from new yard jobs. Site crews are listed separately on the Workers tab and do not take yard jobs.

## Yard overview update
The home page lists configured simulation workers and equipment, their assigned tasks and current availability. These resources are distinct from login accounts. The side parking apron is a dimensioned layout outside the storage polygon; it does not add storage area or implement truck manoeuvring, swept paths or parking reservations. Its initial 10 m by 3.1 m preview uses the requested 6 m by 2.1 m deck, an assumed 3 m cab and 0.5 m clearance on each side. Overall vehicle dimensions and clearance can be saved per yard. Existing truck deck records are preserved. Cages are separately styled mesh frames with editable dimensions; their suggested dimensions are illustrative.


## Worker controls
Workers support select, move, stop, hold and return-to-work orders. Manual movement is server-owned, uses a 0.5 m footprint and 1.4 m/s speed, respects stock obstacles and yard boundaries, and pauses with the simulation. A manually moved worker holds at arrival until returned to automatic work. Assigned handling workers cannot be redirected mid-task. These controls do not yet assign specific packing/loading jobs to a chosen worker, simulate crowd avoidance between workers, or animate operators boarding equipment.


## Forklift mounting
Configured yard forklifts now have a parked footprint and a worker mount/dismount flow. Mount reserves the forklift and walks to its boarding point before attaching the worker. Stop cancels an approach and releases the reservation. A mounted worker and forklift are excluded from automatic jobs; dismount before returning to automatic work. Mounted drivers can now drive, pick up and place ground-level stillages in the yard. Forklift drawings use illustrative dimensions.


## Manual forklift handling
Right-click ground drives a mounted forklift. Select a ground-level stillage and use Pick up; use Place load followed by a ground click to place. Pickup approaches from the left (forks face right); turning radius, stacking and truck loading are not part of these manual controls. Stillages support 0/90 degree placement orientations with conservative rotation clearance. Driving uses a conservative rectangular footprint for forklift plus load. A blocked move stops without releasing cargo. Stop cancels an approach but keeps any carried load. Ground pickup and placement are persisted with ledger events, and manual cargo cannot be edited or assigned to another job. Manual routing does not model pedestrian avoidance.


## Home stockpile (icon grids)
The Home page shows every enabled catalogue component as an icon in four grids: AtPac, Quickstage, Tube & Clip and Miscellaneous (accessories, tools and "other" from every system, plus any product from a system outside the three). A step row (−100 … +100) sets how many pieces one click adds or takes out. Adding uses the same intake rule as before (first available stillage, then a new stillage on the shortest pile) and is recorded as a purchase or original stock. Taking out removes from the highest, most recently added stillage that can be reached, records a STOCK_REMOVED ledger line with the chosen reason, and refuses stock that is reserved, under a stocktake, on a forklift or buried under another stillage. An emptied stillage stays in the yard (it is reused by the next add, or removed with −1 empty stillage). The icons are generic category glyphs, not manufacturer drawings.

## Yard fixtures
The shape editor can place truck entry and exit lanes, a toilet, a yard office and custom fixtures as rectangles inside the boundary, by dragging them on the plan or typing their position and size. Lanes are kept clear of stock only; solid fixtures also block worker and forklift routing and parking spots. Saving fixtures over stored stillages relocates them the same way a boundary change does. The entry and exit lanes are drawn with direction arrows but trucks still park on the side apron; truck driving through the lanes, swept paths and gate control are not simulated.

## Layout planner
The Yard page has a layout planner: drag a stillage to a new spot, or drop it onto another stillage to stack it; whole piles move together and R turns the load while dragging. Check plan shows the ordered instructions; Commit this plan sends them to the crew as a chain of single forklift moves executed in order by the automatic engine (one active plan per yard). The sequencer only picks what is on top and only places where the spot and its supporting stillage are ready; a swap or a pile move sets one stillage down on clear ground first. It refuses plans that leave a stillage on a moving one, overlap, exceed 7 high or the storage height, or have no clear forklift lane. A step can still block at execution time if something changes (the task shows the reason and can be retried); Cancel remaining steps cancels unpicked steps from the end, and a step already on the forklift is placed first. One plan runs per yard or site at a time, and that includes a pile turn. Drag-and-drop is pointer based and has not been validated on touch devices.

## Turning stillages
Select a stillage on any yard or site plan and press the ⟳ Turn button beside it, the Turn button in the bar under the plan or its detail panel, or the R key. The bar says where the stillage is, which way its long side runs (named against the numbered sides) and exactly what the turn will do before you press it. The crew always does the work: a single stillage becomes one forklift (or crane) MOVE marked as a turn, and a pile becomes a chained pile-turn plan after a confirm (the stillages on top are set down nearby, the base turns, and they go back on top). The stillage turns about its middle; if that is blocked it keeps a corner in place; if it cannot swing where it stands it is carried to open ground within 6 m, turned there and brought back. Turning it again puts it back exactly where it was. Only the anchors CENTRE, the four corners and BACK are tried; there is no wider search for a better spot, so a crowded stillage is refused with the names of what is in the way and Plan a new layout is the way out. The plan marks the destination with a dashed ⟳ outline until pickup, draws the carried load at its turning spot (old orientation while carried, new orientation while being set down), and the stillage's slats and fork pockets show its orientation afterwards. Turning is refused for damaged stillages, stock on trucks or forklifts, stillages with a movement already waiting, during an open stocktake, with no forklift or crane, or when the weight is unknown or too great. If the yard fills up after the turn was queued, the task blocks with No room to turn and Retry resumes it once there is space. Supervisors see no turn controls. A turn is a quarter turn as a state change at set-down, not articulated fork or load physics.

## Precise placement and rotation
Place load now opens a dedicated planner with a full loaded-footprint preview, exact integer-millimetre X/Y coordinates, 1/10/50/100/500/1000 mm snap options, nudge buttons and 0/90 degree rotation. Coordinates anchor the top-left of the rotated footprint. Map clicks pin a preview; only Confirm placement moves the forklift. Read-only server validation checks actual stock, yard geometry, route and conservative rotation clearance. Confirmation and arrival revalidate obstacles. Rotation is a simulation state change at placement, not articulated fork or load physics; the manual forklift's access envelope keeps its conservative span × √2 clearance square covering both orientations, while automatic turns use the swept circle of the turning load with the carry-out fallback described under Turning stillages.

## Performance and refresh
The page refreshes every 1 s on Home, Yard, Workers and Overview and every 3 s on other pages and while the shape editor is open. It stops refreshing while the tab or window is hidden and catches up at once when shown again. Your own actions always refresh straight away. The product catalogue is sent once and then only when it changes (a per-company catalogue revision); the regular refresh leaves out catalogue sources and packaging, which the page never shows. On Home and Yard a refresh updates only the panels that changed instead of rebuilding the page. The movement engine ticks each company in its own transaction and yields between companies, so one busy yard no longer holds up page loads for the others; paused companies and companies with nothing moving skip the moving phases. Walking routes use A* search, so paths are equally short but can take a different shape than before. Job countdowns are held in memory and written to the database once per counted second, on every state change and when the server stops (including closing the server window); after a crash up to 1 s of a job's countdown is counted again. The database runs with synchronous=NORMAL in WAL mode: a crash of the app loses nothing, but a power cut or OS crash can lose the last few seconds of changes. The database still lives in the project's data folder; if that folder is synced by OneDrive, the constant small writes make the sync client busy, so a local path (set DATABASE_PATH) is better for a machine that syncs the project folder.

## Loading trucks
Select a stillage on any yard or site plan (or its card) and press Load onto T-01 under the plan or in its details; every truck parked at that yard or site gets its own button. Each truck page also has a Load stillages list: tick the stillages and press Load N selected onto the truck. A stillage with others stacked on it loads as a whole pile after a confirm: the top one goes first and each one below waits until the one above it is on the truck, so nothing is lifted from under another stillage. The crew and a forklift (a crane at a site) always do the work; a request is refused as a whole when any stillage in it is damaged, already moving, locked by a stocktake, too heavy for the payload left or has no room on the deck. With no truck at the yard the row says where the trucks are and offers +1 truck buttons; with no forklift or workers it warns that loading will wait. Loading is for the office (operations.manage); supervisors do not see these controls.
